# Documentation images

- `architecture.svg`: the overall system diagram, shown in full in the root
  README and the architecture guide. It follows the sample path from the sample
  drive to supported devices, beside the read-only saved-Set reports and the
  optional running-Set bridge. It is generated by `scripts/generate_figures.py`;
  do not edit the SVG by hand.
- `audition.png`: the working browser chooser captured at a 960-pixel viewport
  on 10 September 2026. Four synthetic percussive files were prepared using the
  application's normal session builder; one demonstration Keep choice is visible.
  The image demonstrates controls, the waveform and saved state, not AI selection
  or musical quality. Capture with Chrome headless against the running local server,
  using `--window-size=960,620 --hide-scrollbars` so the shot matches the viewport
  rather than Chrome's default window.

Keep screenshots current with the interface and use synthetic demonstration data.
Capture the running application instead of drawing controls that do not exist.

## Diagram style

Diagrams use the figure style of the Eidetic Engineering site, drawn by
`scripts/figure_kit.py`. Reuse the kit for new diagrams so they match.

- **Colour and line.** Paper ground `#f2f3f1`. Every line, arrowhead and
  secondary text uses one muted ink, `#565b58`; component names use `#171918`.
  Lines are 1px.
- **Shapes.** A boundary groups what belongs to one package or place and carries
  an uppercase mono label at its top left. A component has a name and at most
  one detail line. Connections are orthogonal with small filled arrowheads; a
  port and a bus fan one connection out to several components.
- **Dashes mean optional**, and nothing else.
- **Type is sized for where the image is read.** A GitHub README column is 838px
  wide on desktop, so figures are 832 units wide and render at natural size:
  names 15px, details and connection notes 12px, boundary labels 11px.

Wording:

- Reuse words from the prose the figure illustrates, and note the source beside
  each label in the generator.
- Name what happens or what the thing is. Add a detail line only for a fact the
  name does not already give.
- Label a connection only with what passes along it.
- No lists joined by `·` or `+`, no straplines and no title inside the figure;
  the heading and caption around the image do that job.
- Draw the system. Anything that reads as a list belongs in the prose beside it.

To change a figure, edit its spec in `scripts/generate_figures.py` and run
`python3 scripts/generate_figures.py`. CI runs it with `--check` and fails when a
committed SVG differs from its spec, or when a page embedding it uses different
alt text from the figure's description. The figure's height follows its content,
and content reaching into the right margin is an error. Render the result and check that text sits
inside its boxes with Inter and with system fonts: images on GitHub cannot load
web fonts, so most readers see the fallbacks.
